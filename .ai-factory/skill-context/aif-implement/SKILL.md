## Rules

### Gradle build invocation (Metaspace OOM)
**Source**: tech-stack fact (IntelliJ Platform Gradle plugin build; default daemon crashed with `OutOfMemoryError: Metaspace` repeatedly)
**Rule**: When compiling/testing/building this plugin, invoke Gradle as
`GRADLE_OPTS="-Dorg.gradle.jvmargs=-Xmx2g -XX:MaxMetaspaceSize=1g" ./gradlew <task> --no-daemon`.
The default Gradle daemon OOMs on Metaspace on this project. Prefer scoped tasks
(`compileKotlin`, `test --tests "<pattern>"`, `buildPlugin`) over full builds to keep runs fast.

### Adding a Grammar-Kit language
**Source**: codebase convention (adding the WippyJet/Jet language)
**Rule**: To add a new Grammar-Kit language, mirror the WippyLua stack and:
- Register a SECOND codegen pair with `tasks.register<GenerateLexerTask>("generateXLexer")` /
  `tasks.register<GenerateParserTask>("generateXParser")` (NOT the single pre-registered
  `generateLexer{}`/`generateParser{}` DSL), and add both to `compileKotlin`/`compileJava` `dependsOn`.
  Do NOT enable `purgeOldFiles` (its output root is the shared `src/main/gen`).
- The `.flex` references the BNF-generated `<Prefix>Types` token holder, so a **minimal `.bnf`**
  (tokens + trivial root) must exist before the lexer can compile; expand the grammar later.
- `src/main/gen` is regenerated build output (git-ignored) — never hand-edit; delete stale
  generated files when a rule is renamed/removed (no purge).

### IntelliJ HTML-template languages
**Source**: codebase convention (Jet = HTML + `{{ }}`)
**Rule**: For an HTML-with-embedded-expressions language, use the Template-Data-Language API
(`Language` + `TemplateLanguage`, `MultiplePsiFilesPerDocumentFileViewProvider` +
`ConfigurableTemplateLanguageFileViewProvider`, `TemplateDataElementType` with the lexer's
outer-content token + an outer fragment token, `ASTFactory` returning `OuterLanguageElementImpl`).
Cache the `TemplateDataElementType` per data-language. Register the HTML/XML dependency as optional
(`<depends optional="true" config-file="language-<x>.xml">com.intellij.modules.xml</depends>`)
and put the language's extensions in that config file. **Use `com.intellij.modules.xml`, NOT
`com.intellij.modules.html`** — the latter does NOT exist as a module alias in IntelliJ 2025.2
(HTML is the `HtmlTools` plugin; `HTMLLanguage` ships with the XML module). A wrong/absent optional
`<depends>` makes the config file silently not load, so the file type never registers and files
open as plain text — diagnose via `build/idea-sandbox/*/log/idea.log` and the resolved-modules list.
Reference: JetBrains Handlebars plugin.
